# Аналитика: зафиксированные определения метрик

Гниют обычно не данные, а определения: MAU, посчитанный каждый раз чуть по-своему,
хуже отсутствующего. Поэтому запросы живут здесь и версионируются вместе с кодом —
сравнивать срезы между собой можно только если считаны они одинаково.

## Два прибора, два горизонта

| Прибор | Где | Горизонт | Что меряет |
|---|---|---|---|
| `user_activity_day` | Postgres | годы | возврат, DAU/WAU/MAU, адопшен радара |
| `analytics.log` (nginx) | `/var/log/nginx-analytics/` | 90 дней | воронка, пути, тайминги |

Разделение намеренное. Ролап компактен (≤1 строка на юзера в сутки), переживает
редеплой и ротацию — на нём меряется сезонный возврат, который у продукта
событийный и годовой. Лог детален, но живёт короткое окно; он отвечает на вопросы
вида «что человек делал внутри визита», которые в ролап не влезают.

## Важно про исторические данные

`user_activity_day` копится **только вперёд**, с момента выката. Восстановить его
из прошлого нельзя: `user.last_login_at` хранит одно значение и затирается.
Поэтому все запросы про возврат до первой полной недели данных будут пустыми —
это ожидаемо, а не поломка. Частично реконструировать историю действий можно из
`wish.created_at`, `follow_event`, `user_following.created_at`, `push_sending_log`.

То же про `wish.reserved_at`: у 345 резерваций, сделанных до инструментации,
там NULL (легаси) — фильтруйте явно, иначе средние поедут.

## Запуск

```bash
ssh wishes 'docker exec -i wishes-db psql -U wishes -d wishes_db -q' < analytics/retention.sql
```

Лог читается через `jq`:

```bash
ssh wishes 'cat /var/log/nginx-analytics/analytics.log' \
  | jq -r 'select(.user_id != "") | [.ts, .user_id, .route, .status] | @tsv'
```
